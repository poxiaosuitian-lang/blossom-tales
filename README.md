# 拾花物语

支持 Docker Compose 一键部署，详见 [部署指南](docs/DEPLOYMENT.md)。本地需要 Node.js 24 或更新版本，无需安装运行依赖。首次启动需通过环境变量设置管理员密码，随后运行 `npm start`。Windows 可运行 `start.ps1` 启动服务并打开浏览器。

也可以在项目目录运行 `npm start`，再打开 http://localhost:5173 。多用户版本必须通过服务访问，不能直接双击 `dist/index.html` 或使用静态文件服务器。默认监听端口 5173，可通过环境变量 `PORT` 调整；同一局域网玩家可访问服务器电脑的 IP 和端口（需要网络允许连接）。

玩家在「宿主绑定」界面注册或登录，每个账号的红花余额、免费次数、宝库、最近 200 次祈愿记录和保底进度独立保存。抽奖和扣花由服务器结算，刷新页面、切换设备登录及重启服务后均可继续。旧版本浏览器 localStorage 存档不会自动导入账号。

登录入口直接融入完整背景，包含水晶悬浮、旋转星轨、星光粒子和流光动画；登录或注册成功后转场进入祈愿主页，管理员进入管理中枢。系统开启“减少动态效果”时会跳过动画。小屏幕可滚动填写注册表单。

「拾花手册」以九宫格展示当前奖池概率，并集中说明花费、保底与奖励结算；「宿主花笺」显示红花余额和免费祈愿次数。两页采用与主界面统一的晴空水晶长廊背景与一屏布局，花笺入口同步使用银蓝配色。背景由内置 imagegen 参照主背景生成，图片位于 `dist/assets/blossom-dialogs-daylight.png`，完整提示词保存在 `blossom-dialogs-daylight-prompt.txt`。

管理员初始账号由 `ADMIN_USERNAME` 设置（默认 `poxiao`），首次密码由 `ADMIN_PASSWORD` 或 `ADMIN_PASSWORD_FILE` 设置。已有数据库启动时保留原账号和密码。登录后自动进入管理中枢，可查看和搜索宿主、向指定玩家发放红花、逐项设置 9 种奖励概率，以及查看发放和修改记录。普通宿主无法访问管理接口。

管理中枢的「系统设置」可开启或关闭新宿主注册，点击保存后立即生效并持久保存，已有宿主仍可接入和祈愿；登录入口会同步显示暂停绑定提示。默认开放注册，修改会写入系统记录。

「玩家祈愿记录」支持查看全部或指定宿主、刷新和分页（每页 20 条），显示宿主、奖励、祈愿序号、时间以及单抽 / 十连 / 免费类型。宿主档案内也可直接打开该玩家的记录。十连按每次结果记录 10 条，新结果持续保存在服务器；升级时自动补入旧版仍保留的最近 200 次，并标注为历史祈愿，已被旧版清除的更早记录无法恢复。

每个新宿主初始为 0 朵大红花，不发放绑定礼包，红花由系统管理员发放，单抽消耗 10 朵，十连消耗 100 朵。默认基础概率：传说 2%，三种史诗分别为 4.34%、4.33%、4.33%，五种稀有各 17%。管理员保存时概率总和必须为 100%，支持最多两位小数；调整对后续祈愿立即生效。

默认开启十抽史诗及以上、八十抽传说保底，管理员可关闭。开启保底时，传说和史诗概率均需大于 0；触发史诗保底时按三种史诗的设置权重抽取。关闭后保底计数仍累积并封顶，重新开启后按当前计数触发。包含宝库、记录、可跳过的动画和可关闭的音效；联动礼品及互动任务由参与者自行兑现。

账号、密码哈希、会话和奖池设置保存在 `data/university.sqlite`，可用 `DESTINY_DATA_DIR` 指定其他目录。备份时先停止该服务，再复制整个数据目录；不要只复制正在使用中的数据库主文件。启动日志位于 `data/server.log` 和 `data/server-error.log`，启动器记录的服务进程号位于 `data/server.pid`。关闭浏览器不会停止后台服务。

验证：`npm test` 检查抽奖规则、权限、并发结算、账号隔离和重启保存。`npm run test:browser` 检查注册登录、管理操作、桌面和手机页面及抽奖动画，使用独立临时测试数据库，不改正式玩家数据；先运行 `npm ci` 和 `npx playwright install chromium` 安装测试依赖；也可通过 `CHROMIUM_PATH` 指定已有浏览器。测试截图位于 `artifacts/`。

新版奖池共 9 项：传说为蜡笔小新联动（袋子、贴纸、袜子）；史诗为告诉系统 1、2、3 个秘密；稀有为再抽一次、啥也没中、被偷菜一次、被撞 3 次（游戏碰撞）、奖励 20 朵红花。

花笺成长：从 Lv. 1 开始，每完成 10 次祈愿升 1 级，免费祈愿同样计入。累计 0 / 100 / 200 / 300 / 400 / 500 次对应「拾花初识 / 花芽初醒 / 花语渐浓 / 繁花入梦 / 星海花冠 / 花境长明」，之后等级继续增加。等级按服务器保存的累计次数计算，老玩家自动获得对应等级，刷新和切换账号不会重复播放晋阶动画。晋阶时出现花瓣与光环仪式，点击继续或按 Esc 查看抽奖结果；勾选跳过动画或开启减少动态效果时，只显示结果中的晋阶提示。宿主卡分隔线显示本级进度，悬停等级、境界可看下次成长所需次数；宿主花笺内也显示等级。

7 张配图位于 `dist/assets/rewards/`，三个秘密奖励共用 `secret.png`。通过内置 imagegen 生成，完整提示词保存在 `reward-image-prompts.json`；小新联动配图为礼品示意。

抽中再抽一次时，增加 1 次免费祈愿，点击“免费祈愿”消费，不扣大红花，也计入保底。抽中 20 朵红花时直接入账；领取结果和刷新均不重复结算。旧版库存与记录保留并标注为旧版，不参与新奖池。

背景由内置 imagegen 基于用户参考图片进行去除元素与补全生成，并非原图中遮挡区域的精确还原。生成提示词记录于 `background-prompt.txt`。

奖励名称与个人限量：管理端「奖池概率」支持直接编辑九项名称（1–24 字），与概率一起保存；同步主界面推荐、花间好礼、拾花手册、抽奖结果、宝库、玩家与管理端祈愿记录。历史记录按稳定奖励 ID 展示当前名称，改名不改变实际奖励效果或数量。名称、概率共用版本校验，保存写入管理记录。

小新联动奖励（固定 ID `shinchan`，改名后仍适用）每位玩家最多获得 1 份。抽中过的玩家后续概率为 0，其余奖励按原基础权重重新归一化；十连逐次检查，免费祈愿同样受限，80 抽传说保底不再触发，10 抽史诗保底继续。既有多份库存与旧记录保留，不再新增。同账号并发和重复请求不会重复发奖。若剩余可获奖励权重全部为 0，请管理员调整；整笔抽奖撤销、不扣红花和免费次数。新规则按服务器现有库存判断，跨登录和重启保持一致。

音乐与音效：右上角音符按钮统一控制背景音乐和交互音效，默认开启，记住手动静音设置。浏览器若限制自动播放，会在首次点击、触摸或键盘操作时启动。背景曲「花间晴昼」为本地 Web Audio 合成的原创 16 小节舒缓旋律（72 BPM），搭配柔和琴音、和弦与空间混响，无需下载音频或联网。点击、祈愿、普通/传说揭晓、领奖和晋阶分别使用轻柔提示音；切到后台暂停，返回继续。`npm run test:audio` 验证默认状态、实际音频信号、开关、偏好保存和后台暂停。
